# Перенос tko.megaev.ru → ioo.megaev.ru

Миграция выполняется в два этапа, чтобы не направлять проверку GitHub Actions
на домен, который ещё не включён на VPS.

1. DNS `ioo.megaev.ru` должен возвращать `185.200.179.49`. Временный virtual host
   `ioo-acme.conf` нужен для выпуска сертификата через существующий webroot
   `/var/www/letsencrypt`. Выпустить отдельный сертификат `ioo.megaev.ru`.
2. После доставки `switch-to-ioo.sh` автодеплоем запустить от root:

   ```bash
   ssh -t root@185.200.179.49 'bash /opt/tko-ioo/server/deploy/switch-to-ioo.sh'
   ```

Скрипт использует ту же блокировку, что и автодеплой. Перед изменениями копирует
файл настроек и затрагиваемые конфигурации в `/root/ioo-switch.XXXXXX` с доступом
только для root. Значения API-ключа не выводятся. Устанавливаются окончательные
HTTP/HTTPS-конфигурации нового домена, `PUBLIC_ORIGIN` меняется на
`https://ioo.megaev.ru`, служба сайта перезапускается и Nginx перечитывает настройки.

После асинхронного reload ожидается готовность HTTPS: до 30 попыток с проверкой
цепочки и имени сертификата на каждой попытке. Временный старый сертификат
не вызывает немедленный откат; постоянно неверный сертификат проверку не проходит.
Проверяются HTTPS `/healthz` и принятие нового `Origin` API без обращения к ИИ.
При ошибке восстанавливаются прежние настройки, файлы Nginx и службы.
Контейнеры бота, DNS, файлы Node.js, ключ OpenAI и лимиты не меняются.

Старый `tko.megaev.ru` отключается **без перенаправления**: HTTP возвращает 410,
TLS-соединения отклоняются. Явный блок `tko-disabled.conf` нужен, чтобы старый
адрес не открывался через wildcard DNS и default virtual host. Старый сертификат
для этого блока не требуется.

URL проверки, environment в `.github/workflows/tests.yml` и ссылки в документации
переключены на `ioo.megaev.ru`. Проверить успешный деплой с новым URL.
Затем удалить больше не используемый
сертификат старого домена, чтобы Certbot не пытался продлевать его:

```bash
ssh -t root@185.200.179.49 'certbot delete --cert-name tko.megaev.ru --non-interactive'
```

Глобальный hook продления сертификатов уже перечитывает Nginx. При новой
установке использовать обновлённые `nginx-http.conf`, `nginx-https.conf` и
`server/.env.example` с доменом `ioo.megaev.ru`.
