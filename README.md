# Выгрузка общих сведений по ТКО

Веб-приложение для подготовки формы «Выгрузка общих сведений»: сводит реестр
источников образования отходов (ИОО) с нормативами накопления ТКО, считает
массу, объём и коэффициент плотности и заполняет исходный файл формы.

Расчёт и обработка реестра выполняются в браузере. Документ нормативов
передаётся ИИ через прокси; из реестра передаются только первые строки для разметки.

## Что делает

1. **Сравнение нормативов.** Из файла нормативов распознаются категории
   потребителей и значения по массе (кг/год) и объёму (м³/год) с приведением
   размерностей (тонны → килограммы, литры → м³). Наименования категорий формы
   сопоставляются с наименованиями нормативов по схожести с учётом расчётной
   единицы (человек / м²).
2. **Ручная проверка.** Любое соответствие можно изменить: выбрать другой
   норматив, задать формулу вида `[n5] + [n7]` (поддерживаются `+ - * /` и
   скобки) или ввести значения вручную. Правила действуют до конца сеанса и
   выгружаются в JSON для повторного применения.
3. **Выгрузка нормативов.** В форму добавляются столбцы «Норматив по массе,
   кг/год» (L) и «Норматив по объему, м³/год» (M).
4. **Консолидация реестра.** Категории с разными единицами измерения
   сопоставляются отдельно. На шаге 3 и в отчёте показаны единица измерения
   и процент сходства с выбранной категорией формы, в том числе при ручном выборе.
   Данные сводятся по зоне деятельности и выбранной
   категории потребителя: столбец G — сумма расчётных единиц, столбец F —
   количество источников (источники с нулевым количеством единиц не считаются).
   Количество и порядок строк, а также столбцы A–E не изменяются.
5. **Расчёт.** H — масса в тоннах (норматив в кг × единицы ÷ 1000),
   I — объём в м³, J — плотность (масса ÷ объём). Расчёт ведётся от точной
   суммы расчётных единиц; в столбец G пишется округлённое до целых значение.
6. **Форматирование.** G — целое, H, I, J — два знака после запятой,
   пустые значения в F–J заменяются нулями, выравнивание по центру
   по горизонтали и вертикали. Столбец K не заполняется.
7. **Проверка.** Сверка итогов с реестром, поиск данных, не попавших в форму,
   неподтверждённых автосопоставлений, расхождений расчётной единицы и
   арифметических ошибок.

## ИИ-извлечение нормативов

После загрузки ИИ получает исходный документ целиком и возвращает **все нормативы**,
а не координаты столбцов. PDF передаётся как документ вместе с изображениями страниц:
сканы без OCR и сканы с повреждённым текстовым слоем тоже доступны модели.
Из DOCX извлекаются все абзацы и таблицы в исходном порядке, признаки объединения
ячеек, сноски и поддерживаемые вложенные изображения. Из Excel/ODS передаются все
листы и строки. Поддерживаются также TXT/CSV (UTF-8), PNG, JPEG, WebP и GIF.
Другие форматы, например старый Word `.doc`, нужно предварительно сохранить в PDF.

Для каждого норматива модель возвращает:

- полное название категории и контекст (территория, тип населённого пункта,
  благоустройство или срок действия);
- расчётную единицу;
- исходную массу и/или объём, размерность, период и количество расчётных единиц;
- место в документе и короткую выдержку с исходными значениями.

Разные территориальные варианты и расчётные единицы остаются отдельными записями.
Если в документе есть только объём, масса остаётся неизвестной: плотность не
придумывается. Строки с прочерками одновременно по массе и объёму сохраняются
с пометкой «Не указаны в документе» и предупреждением, не отклоняя весь справочник.
Настоящие нули сохраняются как нули. Программа приводит исходные числа к кг/год и м³/год на одну единицу:
тонны × 1000, граммы и литры ÷ 1000, месячные значения × 12, суточные × 365,
значения на 100 единиц ÷ 100. Округление выполняется при формировании результата.

Завершённый структурно корректный ответ автоматически используется в сопоставлении.
На шаге 1 можно раскрыть **весь** справочник, увидеть источники и скачать отдельный
Excel, даже если реестр и форма ещё не загружены. Ошибки распознавания возможны:
значения, единицы и выбранный территориальный вариант нужно проверить по документу.
Структурная проверка ответа не доказывает правильность чтения изображения.

Большие документы не обрезаются незаметно. Пределы: 16 МБ на исходный файл,
400 000 символов для текстового представления, 50 вложенных изображений,
1000 нормативов в ответе. При превышении лимита, незавершённом ответе или
нечитаемых значениях результат не применяется; приложение предлагает разделить
документ на части. Предыдущий результат сохраняется. При недоступности ИИ
доступен встроенный разбор DOCX/Excel/PDF с текстовым слоем, который может найти
не все нормативы; ошибка ИИ отображается явно.

Реестр ИОО обрабатывается иначе: модели передаются только название листа,
шапка и первые строки, чтобы определить роли столбцов. Полный реестр остаётся
в браузере. Числа из него читает и суммирует программа.

Ключ Anthropic хранится в Cloudflare Worker `tko-ioo-ai`, секрет
`ANTHROPIC_API_KEY`. Адрес прокси встроен в программу; свой адрес можно задать
на шаге 1. При переходе со старой версии нужно **обновить и Worker, и сайт**:
инструкция — в [worker/README.md](worker/README.md). Старый Worker, умеющий только
разметку, не поддерживает задачу `norms-extract`; приложение сообщит об этом.

## Результаты

- отдельный справочник извлечённых нормативов с единицами и источниками (.xlsx);
- обновлённый файл общих сведений (исходный файл с заполненными столбцами);
- отчёт: таблицы соответствий, расчёт по строкам, аналитика проверки;
- файл правил сопоставления для повторного применения.

## Исходные файлы

| Вид | Формат | Как распознаётся |
| --- | --- | --- |
| Выгрузка реестра ИОО (можно несколько) | .xlsx | столбец «Категория потребителя»; по возможности «Количество расчетных единиц», «Зона деятельности», «Муниципальное образование» |
| Выгрузка общих сведений (шаблон) | .xlsx | столбцы «Расчетная масса», «Расчетный коэффициент плотности» |
| Нормативы накопления ТКО | PDF, DOCX, Excel/ODS, TXT/CSV, изображения | таблица с наименованиями категорий и числовыми нормативами — по шапке («куб.м …», «кг …») либо по самим значениям («0,247 тонн/1 проживающего человека в год») |

Названия файлов значения не имеют — вид определяется по содержимому и при
необходимости меняется вручную в списке загруженных файлов.

### Сеанс расчёта

Каждый расчёт начинается с чистого листа. Ничего не переносится между
сеансами: после перезагрузки страницы нет ни файлов, ни категорий, ни правил
сопоставления, ни разметки, заданной помощником. Так исключено самое неприятное
— когда правило от прежнего приказа молча применяется к новому.

Внутри сеанса:

- новый файл общих сведений считается началом нового расчёта: прежние файлы и
  правила сбрасываются, о чём приложение сообщает;
- приказ в расчёте один, поэтому новый заменяет прежний;
- выгрузок реестра может быть несколько, и они накапливаются; лишнюю убирают
  кнопкой в списке файлов;
- кнопка «Начать заново» сбрасывает всё, не перезагружая страницу.

Правила, над которыми поработали, переносятся намеренно — файлом правил
(.json) на шаге 6.

Если в выгрузке реестра нет количества расчётных единиц, разбор всё равно
выполняется: заполняется столбец F (количество источников), а G, H, I и J
остаются нулевыми. Об этом сообщает отдельная ошибка на шаге проверки.

### PDF и сканы

Основной путь — передача исходного PDF в мультимодальную модель. Текстовый слой
для него не обязателен. Это позволяет читать документ с неправильным OCR, где
буквы и цифры искажены, и таблицы, разорванные между страницами.

Резервный встроенный разбор использует pdf.js и восстанавливает таблицы по
координатам текста. Для PDF без текстового слоя резервный разбор недоступен,
но это не блокирует основной путь через ИИ.

## Запуск

Приложение статическое, сборка не требуется. Локально:

```bash
python3 -m http.server 8000
# затем открыть http://localhost:8000/
```

Открывать `index.html` напрямую из файловой системы нельзя: браузер
блокирует загрузку модулей по протоколу `file://`.

## Публикация

Сайт: **https://kamegaev.github.io/tko-ioo/**

Публикуется на GitHub Pages рабочим процессом `.github/workflows/pages.yml`
при изменениях в `main`; можно запустить и вручную из вкладки Actions.
Публикация возможна только с `main`: окружение `github-pages` по умолчанию
не пускает остальные ветки.

## О зависимостях

`vendor/` содержит JSZip, SheetJS и pdf.js — внешних запросов приложение
не делает.

pdf.js (Apache-2.0) весит около 1,7 МБ — больше остальных вместе взятых, —
поэтому подгружается только тогда, когда открывают приказ в PDF. Кто приносит
.docx или .xlsx, эти файлы не скачивает вовсе.

SheetJS в npm остановился на версии 0.18.5, у которой есть две известные
уязвимости (загрязнение прототипа и ReDoS). Обе срабатывают только на
специально составленном файле: приложение статическое, работает с файлами
самого пользователя, не имеет сервера и чужих данных, поэтому версия
оставлена осознанно. Обновление до 0.20.x возможно вручную — файл
`xlsx.full.min.js` с cdn.sheetjs.com кладётся в `vendor/`.

## Разработка

```bash
npm install   # только для тестов
npm test
```

Тесты закрывают разбор файлов, сопоставление наименований, вычисление формул,
расчёты и запись результата; в них воспроизводится «сложный» вид выгрузки
ФГИС — с префиксом пространства имён и заниженным `<dimension>`.

### Устройство

```
index.html            интерфейс
css/app.css           оформление
js/lib/               ядро: текст, размерности, сопоставление, формулы, расчёт, проверка, OOXML
js/parse/             разбор нормативов, реестра и шаблона
js/parse/pdf-layout.js восстановление таблиц из PDF по расположению текста
js/parse/pdf-scan.js  то же для сканов: по просветам между столбцами
js/ai/                ИИ: полный документ, извлечение нормативов, проверка ответа и разметка реестра
js/export/            запись в шаблон и формирование отчёта
js/ui/                отображение
vendor/               JSZip и SheetJS (подключены локально, без внешних запросов)
worker/               прокси к модели (в состав сайта не входит)
```

Шаблон формы записывается правкой XML внутри исходного файла, а не пересборкой
книги: выгрузка ФГИС использует префикс пространства имён (`<x:worksheet>`) и
объявляет `<dimension>` лишь для первых строк, из-за чего распространённые
библиотеки читают её неполностью или не читают вовсе. Такой подход сохраняет
исходный файл во всём, что программа не изменяет.
